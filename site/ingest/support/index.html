Ingest / Support

Cards, copies, and metadata.

What Ingest needs, what it reads, and what to do when something does not go the way you expected. If none of this covers it, write to me.

What you need

Ingest runs on macOS 15 or later, on Apple silicon only. There is no Intel build, so an Intel Mac cannot open it. To check your Mac, open the Apple menu and choose About This Mac: the Chip line reads Apple M1 or later.

Open the disk image and drag Ingest to your Applications folder. There is no account, no subscription, and no license key. The app is signed and notarized by Apple, so it opens with a double click the first time.

You do not need to install anything else. The tool Ingest uses to write metadata is built in.

Cameras and files it reads

Ingest is fast because it never decodes a raw file. It finds the JPEG preview the camera already wrote inside the raw file and shows you that. This is why it can only be fast for formats it knows how to open.

FileWhat happens
Sony .ARWFull speed. The camera writes a small preview and a full size JPEG inside the file, and Ingest reads whichever it needs.
Fujifilm .RAFFull speed. The embedded JPEG is found from the file header.
.JPG and .JPEGFull speed, including the second image that Sony cameras store for fast preview.
.HEIC and .HEIFOpens and browses.
.MP4 and .MOVBrowses and plays, with a poster frame in the grid. Sony clip sidecars travel with the file when you ingest.
Other raw filesDNG, CR3, CR2, NEF, ORF, and RW2 are recognised as photographs, but Ingest cannot read their previews yet, so they appear without a thumbnail. Support for them is a question of writing one more reader, not of changing the design.

Files that are never treated as photographs: sidecars such as .XMP and .THM, camera database and index files, and anything beginning with a dot.

Memory cards

Insert a card and it appears in the sources list within about a second, with its name and free space. By default Ingest opens it for you. That is a setting in Settings, General, if you would rather it just sat in the list.

Ingest never writes to a card. No ratings, no keywords, no renames, no Finder tags, no deletions except the ones you ask for by name after a copy has been verified. That holds however you opened the card, including when you open a folder that happens to live on one. Metadata you add while culling is remembered and applied to the copies during ingest.

If a card does not appear, check that it is mounted in Finder. Ingest looks for a DCIM folder to recognise a volume as a card. A card formatted by something other than a camera may not have one, in which case open it with ⌘O as an ordinary folder.

To eject, press ⌘E. Ingest closes everything it has open on the card first, so eject does not fail with a file in use. If macOS still refuses, another app is holding the card. Pulling a card without ejecting does not crash Ingest. It notices and closes the source.

The first hour

The keys are the part worth learning, and there is a way to practise them that cannot hurt anything. Choose Help, then Open Practice Folder. Ingest builds about thirty throwaway images and opens them, and the status bar tells you which keys to try. Nothing in that folder matters, so tag, reject, rate, and undo as roughly as you like.

Press ? at any time for the shortcut sheet, or ⌘K to search every command by name. Holding ⌘ for a moment shows the keys that work where you are. The complete list lives on the shortcuts page, and the quick start walks one card from insert to finished folder.

Thumbnails are slow or missing

A grid of Sony or Fuji raw files should fill immediately. If it does not, the likely cause is that the files are on a slow connection, such as a card reader on a hub or a network volume. Ingest reads only a few megabytes per photograph, but it still has to read them.

Thumbnails that are expensive to build are cached on disk, under 2 GB, and cleared from Settings, Advanced. Clearing the cache is safe and never touches a photograph.

A photograph with no thumbnail at all is usually a raw format Ingest cannot read yet. See cameras and files it reads.

A copy did not finish

Ingest copies to a temporary name, flushes it to disk, reads the copy back, compares it to the source, and only then gives it its real name. Nothing is ever overwritten. If something goes wrong part way, the files that were already copied and verified are kept and the rest are not, and the receipt records what happened.

The Ingest button is dim
The reason is printed beside it. The usual ones are no destination chosen, nothing in the scope you picked, a template that will not parse, or two photographs that would end up with the same name.
Names collide
Ingest refuses rather than quietly adding a suffix. Add {seqn} or {seq} to the template so every name is different. See collisions.
Not enough space
The sheet checks free space before it starts and tells you, rather than filling the disk and failing at photograph two hundred.
Deleting from the card
Only files whose copies verified at every destination are deleted. Choosing to delete everything asks you to confirm, and that choice is never remembered for next time.

Lightroom or Photos does not show my keywords

Ingest writes keywords, captions, titles, ratings, colour labels, and GPS into the files themselves, in the fields Adobe and Apple actually read. It does not write sidecar files, because Apple Photos ignores them.

Two things to check first. Metadata is never written to a card, so if you added keywords while culling, they are applied to the copies during ingest and you should look at the copies. And ratings and labels are written in the background a couple of seconds after you stop pressing keys, so a file read the instant you rated it may not have caught up.

The writing is done by ExifTool, which is included in the app. Ingest keeps ExifTool's backup of each file until it has read the file back and confirmed the write, then removes it. If the read back does not match, the original is put back.

If Settings, Advanced reports that the metadata tool is not ready, turn Use the built-in exiftool back on. The built-in copy runs with the Perl that ships with macOS. If a future macOS removes Perl, that switch and a copy installed with Homebrew are the way back.

Permission prompts

macOS asks before an app reads a removable volume. Allow it, or Ingest cannot see your cards. If you dismissed it, the switch is in System Settings, Privacy & Security, Files and Folders.

Two prompts appear only if you use the features that need them. An action that imports into Apple Photos asks for access to your photo library. An action that runs a Shortcut asks for permission to control Shortcuts. Neither is requested until you build an action that uses it.

Coming from Photo Mechanic

The habits carry over. T tags, the arrow keys move, ⌘G is ingest, and {seqn} is the sequence number that never repeats. Brace tokens in name templates use the same spelling, so a pattern you have typed a thousand times still works.

Three differences worth knowing. Marking keys do not advance by default, which matches Photo Mechanic, and you can turn advancing on in Settings, Culling. Rejects are hidden by default and the toggle is visible in the toolbar, so nothing disappears without saying so. And stars and colour labels use the Lightroom keys, 1 to 5 and 6 to 9, written into the files so Lightroom sees them on import.

Settings, Shortcuts lists every command. Click a shortcut or focus it with Tab and press Return to record a new one. Navigation keys and standard Mac editing shortcuts stay fixed; Settings explains any conflict.

Updates

Choose Ingest, then Check for Updates. Automatic checking is off until you turn it on in Settings, General. An update is only installed if it carries a signature made with my key.

What each version changed is in the release notes. Nothing about your Mac is sent when Ingest checks. The privacy page says exactly what does and does not leave the machine.
